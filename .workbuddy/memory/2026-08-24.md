# 2026-08-24

## ES8311 音频播放成功! (U盘 WAV 顺序播放)

### 完成内容
- 实现 ES8311 codec 播放 (`main/audio_player.c/h`): I2C(GPIO7/8) + I2S(MCLK13/BCLK12/WS10/DOUT9) + 功放(GPIO53)
- U 盘连接后自动收集根目录 WAV → 顺序循环播放 (`main/main.c`)
- 依赖组件: `espressif/esp_codec_dev ^1.6.0`
- **实测播放成功**: test.wav (48MB, 48kHz/2ch/16bit, ffmpeg 生成) 正确解析并播放, PA 使能正常

### 关键经验 (重要!)
1. **WAV 解析块扫描 bug**: ffmpeg 生成的 WAV 在偏移 36 有 `LIST` 块(含 INFO 元数据), data 块在 78 处
   - 若从偏移 44 开始扫块, 会把 `INFO` 当块名, chunk_size 读到 `ISFT` ASCII (0x54465349 ≈ 1.4GB) 导致解析错误
   - **修复**: 从偏移 36 开始扫描块 (正确识别 LIST 并跳过)
2. **采样率不匹配 (声音失真但能听到)**: `esp_codec_dev_open()` 在设备已打开时**直接返回** (esp_codec_dev.c "Input already open")
   - 初始化 open 用 16000Hz 后, 播放 48000Hz WAV 时再次 open 不生效 → I2S 一直 16000Hz, 音调变 3 倍
   - **修复**: 播放前先 `esp_codec_dev_close()` 再 `esp_codec_dev_open()` (强制重配采样率)
   - **验证**: 日志 `I2S_IF: STD: TX, sample_rate_hz: 48000` 确认生效
3. **configdep 反复 Permission denied 的根治**: 环境变量 `IDF_CONFIGDEP_ENABLE=0` (build_esp32.ps1)
   - `-DCONFIGDEP_ENABLE=False` 无效! idf.py 会强制追加 `-DCONFIGDEP_ENABLE=True` 覆盖 (tools/idf_py_actions/tools.py:771)
   - configdep 是 Windows 上 .obj.d 文件锁定问题的元凶
4. **编译日志文件被占用**: build_log.txt 被残留进程占用时 Out-File 失败, 编译静默失败 (EXIT=2 但无错误)
   - 需要先杀进程再删 build_log.txt
5. **中文文件名**: FATFS codepage 936 + API_ENCODING_UTF_8 仍不能正确显示 `唯一.wav` (显示成 .wav)
   - 用户改名为 test.wav (ASCII) 后正常 → 中文文件名在 FATFS 上仍有编码问题, 待解决
